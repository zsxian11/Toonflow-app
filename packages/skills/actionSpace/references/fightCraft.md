# 打斗与空间写法

供 `actionSpace` 写方案、资产与分段分镜时使用。目标模型以当前视频节点配置为准；单段时长与参考数量以 `node:getConfig` 为准，不编造平台上限。

## 任务类型

- **新建**：用户给想法 → 按分步交付走方案 → 资产 → 分段分镜 → 预演投喂。
- **优化**：用户贴已有打戏提示词 → 输出【诊断】3–5 条、【优化版】、【改了什么】；人物与结局不改。
- **修改**：在本轮已有方案上改 → 只重出受影响步骤。
- **续写**：用户发上一段实际结尾 → 按实际改写【承接】再写下一段。

缺时长、画幅、风格等按默认补全并在【本版假设】一行写明；不追问。仅当用户要求先问、或需求自相矛盾时最多问 3 个带选项的问题。

## 方案（第 1 步）须含

- 【戏核】谁 vs 谁、为何必打、强弱错位、赌注、凭什么赢；场地至少一样东西参与战斗。
- 【对阵】身份、兵器、打法、主色；错位一项。
- 【场地】地点｜固定方位参照｜地面介质｜≤3 地标｜高差｜可破坏物｜主光方向。
- 【分段与节拍】段号｜全片时间｜地点｜发生什么｜段末清晰可读姿态。
- 【资产清单】资产 ID｜名称｜用途｜在哪几段使用。

时长容量：短段一次交手或一次优势转换；超过当前模型单段上限则分段，切口选刃相抵、落地制动、被逼到墙边等可读姿态，不选高速模糊帧。

## 动作铁律（每段落实）

1. 开画即在动作里，不拍长时间对峙摆架势。
2. 每击有结果；对手应答须改变下一招（变线、换位、改高度或抢主动）。
3. 接触瞬间受力部位立刻反应，再传到躯干与脚下；特效与接触同帧。
4. 反馈分级：兵器/身体 + 环境介质；轻中重拉开幅度，禁用空词堆砌。
5. 边移动边打；位移因攻防发生；每段至少一次改变画面轮廓的身体路线。
6. 末态即起势；切镜继承位置、朝向、持握与战损，不复位重新举兵器。
7. 越打越凶，全片至少一次预期反转；被破防方不能立刻满血防守。
8. 快节奏时用连击数量与串法描述（如「刺—挑—横削三连」），不用「每 0.2 秒一击」类时间戳控频。
9. 一回合一连续镜头；每镜 1 个主动作亮点 + 1 个摄影任务。
10. 先定观众要看清什么再选机位；运镜不能代替人物换位。
11. 特效贴附实体或有起点→路径→落点；不遮接触点与人脸。
12. 胜负拍清接触与失效支撑；战损永久继承；收尾留余势不定格收兵器。

群战分层：交手层（看得清招式的少数人）／压迫层（逼近补位）／氛围层（队列纹理）。主要可辨主体宜少；杂兵统一形象。

## 资产约定

- **C00x** 角色设定；**W00x** 兵器；**S00x-A/B** 场景建立/反打视角；战损版如 **C001-D1**。
- 角色设定图要「好打」：袖口收窄、束发、少飘带；主角与对手在主色、轮廓、兵器长度上至少两项拉开。
- 场景图服务可打性：方位参照、地标、高差、可破坏物；无人物。
- 锁定卡：8–12 短语，出图核对与写分镜复述外观时取词。
- 第 2 段起外观、站位、战损与【承接】一致；战损出现后下一段改传战损版，完好态角色图不再上传。
- 与项目状态矩阵对齐：production `stateKind=damage` / novelPipeline `states[].kind=damage` 的采用图即本处战损版；分镜 `characterStateIds` 从下一镜起改为该变体 id。

## 分段分镜代码块结构

段标题在代码块外。块内顺序：

1. （第 2 段起）向后延长上一段成片：从最后一刻接着打，不重复已发生内容。
2. 【承接】（第 2 段起）复述位置、朝向、距离、姿态、持握、冲势、战损、环境残留。
3. 【基础设定】画幅时长、参考素材职责、风格、节奏总览、场地材质、光色、特效、声音。
4. 【分镜时间轴】每窗：机位 → 攻方起手与连击串 → 守方应答 → 反馈 → 回合结果与末态。
5. 【硬约束】开画即交锋、接触有结果、切镜不复位、兵器与人数锁、战损持续、无血呈现等。
6. 【负面】通用底层 + 本段 2–4 条针对性风险。

有白模参考视频时，基础设定中的职责写法见 [白模职责声明](previsDuty.md)。

## 交付前自检（心里做，不写进回复）

- 删掉特效与风格词后，是否仍看得懂谁攻谁守、局面怎么变。
- 删掉某次走位后攻防是否不变（若不变则是装饰步法）。
- 删掉对手后连招是否照样成立（若成立则对手是木桩）。
- 段末态与下一段【承接】是否逐项一致；参考编号与上传对照是否对得上。
