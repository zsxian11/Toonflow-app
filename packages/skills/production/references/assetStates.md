# 剧情状态资产矩阵

在已确认剧本与基础资产之后，按剧情需要提案**服饰 / 战损 / 场景时段**等可持续变体，批量出图并写回 `制作/state.json` 的版本关系。瞬时表情、单镜姿态、纯换机位不建变体。

本文件服务 production；novelPipeline 的角色表字段见该技能 `characters.md`，分镜映射见 `shotSheet.md`。打斗战损 ID 约定与 `actionSpace` 的 C001-D1 一致。

## 何时提案

- `gates.script` 已确认，且基础角色/场景/道具至少有一份采用图或明确待出图清单。
- 对照已确认剧本（及本集大纲）：换装、变身、持续伤势/破袖、场景日夜/晨昏等**跨片段仍可识别**的变化。
- 每个父资产通常 0～5 个有依据变体；没有需要时写「无需状态变体」并继续。

## `制作/state.json` 资产字段扩展

`characters` / `scenes` / `props` 每条在原有 `id`、`name`、`version`、`adoptedPath`、`canvasPath`、`nodeId`、`usedBy` 之外，可选用：

| 字段 | 说明 |
| --- | --- |
| `parentId` | 变体指向基础资产 `id`；基础态省略或等于自身 `id` |
| `stateKind` | `base` / `costume` / `damage` / `timeOfDay` / `other` |
| `stateLabel` | 短名，如「抓鸡劲装」「仙门大会服」「庭院·夜景」「袖破战损」 |
| `trigger` | 引发该状态的场次/事件一句；基础态可空 |
| `adoptedPath` | 该状态采用图；变体未出图前可空，**不得**把父图路径冒充变体 |

变体使用独立 `id`（如 `linFengCostumeArena`、`linFengDamageSleeve`、`yardNight`），不要覆盖基础态的 `adoptedPath`。基础态换图只升自己的 `version`，并只把仍引用旧基础图的 `usedBy` 片段标回 `ready`。

## 提案与出图顺序

1. 读剧本与现有资产表，列出「父 id → 变体清单（kind、label、trigger、适用片段）」；展示给用户确认全部 / 部分 / 跳过。
2. 已跳过的变体不得当作已有参考图；受影响片段标待素材，不宣称可整集生成。
3. 对确认子集：在资产画布为每项建图片节点（或以父图为参考做局部改图）；提示词写清**不变项**（脸、体型、识别锚点）与**仅改变项**。
4. 用户采用后写入该变体的 `adoptedPath`、`nodeId`、`canvasPath`，`version` 从 1 起；`usedBy` 只列将使用该状态的片段 id。
5. 全部确认的基础+变体齐备（或缺口已记录）后再把 `gates.assets` 视为可进入片段制作；缺变体时只推进不受影响的片段。

## 片段接线

- 片段视频节点连接**本段实际状态**的采用图，不默认永远连基础三视图。
- 提示词里写清 `{{ref N}}` 对应哪一状态（如「大会服」「夜景庭院」）。
- 战损：破损发生的那一段仍可参考完好态，并在正文写清破损时刻；**下一段起**改连战损变体，不再上传完好态角色图（与 actionSpace 一致）。

## 自检

- 每个变体能指回 `parentId`，且父图真实存在或已记录缺口。
- 无「只有基础图却声称已是战斗服/夜景」的冒充。
- 分镜或片段的状态 id 与连入节点的采用路径一致。
